【Steel 報價合併與核對工作規則】

一、輸入與責任

1. 以目前已確認的完整 `ocr_result` 為唯一訂單範圍，讀取已完成的 `system_order_chunk` 明細與 `quote_lineage`；本工作流程的輸入只包含保存後的列與追溯資料，不要求或接收原始查價 payload。
2. 各分組結果的 `sourceRowId`、`kind`、`lookupCallId` 與 candidate identity 是列的追溯依據。只接受已完成且可追溯的分組結果；不可用推定、摘要或部分結果補足缺列。
3. 本工作流程不呼叫 `search_price_candidates`，不呼叫 OpenAI Python，不重新檢視圖面，也不改寫類別規則產生新的候選或計價量。

二、合併與核對

1. 先依完整訂單的來源列順序排序，再把每筆材料列與該來源列的全部加工列放在同一群組；群組第一列必須是材料列，加工列依來源確認順序緊接其後。
2. 每筆來源材料必須恰有一筆材料列。不得合併、重複、刪除、補造或交換來源列；任何缺少、重複、錯配或未完成的分組結果都不得宣告完成。
3. 合併後只保留分組結果已接受的完整欄位值。不得更改 `數量`、尺寸、來源件號、candidate-owned 欄位、計價基準、單價、單重或總數；未知值維持空白並記錄具體待確認原因。
4. 逐列檢查缺少的規格、數量、尺寸、重量、計價量、單價、候選匹配、fallback 或低信心判斷。每一項都列入同一張 `manual_review`，不可用說明文字或省略列取代。

三、輸出

1. 輸出一張完整的 `## system_order` 表，以及有待確認事項時才輸出一張最後的 `## manual_review` 表；與本次核對直接相關且符合既有輸出規則的 AI 補充 Markdown 可保留。`system_order` 固定欄位依序為：`型號`、`品名規格`、`材質編號`、`單位`、`數量`、`單重`、`總數`、`單價`、`計價基準`、`公式編號`、`厚度`、`寬度`、`長度`、`肚`、`類別`、`備註`。
2. `manual_review` 固定欄位依序為：`來源表格`、`來源件號 / 項次`、`問題欄位`、`目前判斷`、`需確認內容`、`影響範圍`。沒有事項時不得輸出空表。
3. 每筆 `manual_review` 的來源請優先填 `來源表格=system_order`、`來源件號 / 項次=quote_lineage` 中對應的完整 `sourceRowId`；若以來源資料定位，兩欄必須精確對應同一筆 `來源` 與 `零件編號`，不可只填會與其他列相同的數字或片段文字。
4. `system_order` 只能有一個標題、一張表頭及完整資料列；不得輸出分組結果標題、重複表頭、控制資料、candidate 原始資料或 lineage sidecar。
5. 本工作流程不輸出 `customer_quote`、完成總結句、報價控制訊號或其他報價 sidecar；`manual_review`（若有）必須是最後一張表，其他適用補充 Markdown 依既有輸出規則排在它之前。
