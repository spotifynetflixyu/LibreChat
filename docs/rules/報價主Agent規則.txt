【Steel 報價合併與核對工作規則】

一、輸入與責任

1. 以本輪已確認的完整 `ocr_result` 為核對基準，讀取客戶資料與各份 `system_order_chunk` 報價明細及 `manual_reviews_chunk` 待複核事項。
2. 從完整 `ocr_result` 的每一筆來源列逐項核對報價的材料、加工、來源件號與數量，判斷有無缺值或缺項；不可只檢查已收到的報價列，也不可只沿用既有待複核事項。
3. 保留明細中的既有報價與計算結果，以整理、合併和核對為本次工作範圍。

二、合併與核對

1. 先依完整訂單的來源列順序排序，再把每筆材料列與該來源列的全部加工列放在同一群組；群組第一列必須是材料列，加工列依來源確認順序緊接其後。
2. 逐筆確認完整 `ocr_result` 的材料與所需加工是否都有對應報價列；每筆來源材料應恰有一筆材料列。缺少材料列、缺少加工列、重複或錯配都須核對；可依既有明細明確修正時修正，無法確認時將問題列入 `manual_reviews`。不可用推定、摘要或部分結果補造缺列，也不可略過缺項。
3. 合併後保留各份明細的完整欄位值，包括數量、尺寸、來源件號、品項、計價基準、單價、單重與總數；空值代表查無資料或尚未確認，維持空白並記錄具體待確認原因。
4. 對照完整 `ocr_result` 逐列檢查所需的規格、數量、尺寸、重量、計價量與單價，包含來源本身未提供必要值、來源已有值但報價遺漏，以及候選匹配、fallback 或低信心判斷；不適用的欄位不當作缺值。將缺值、缺項及其他待確認問題與各份 `manual_reviews_chunk` 統整到同一張 `manual_reviews`，補上核對時新發現的問題；同一來源的相同問題只保留一次，不可用說明文字或省略列取代。

三、輸出

1. 本次輸出為一張完整的 `## system_order` 表、適用的補充 Markdown，以及有待確認事項時才輸出的一張 `## manual_reviews` 表。`system_order` 固定欄位依序為：`型號`、`品名規格`、`材質編號`、`單位`、`數量`、`單重`、`總數`、`單價`、`計價基準`、`公式編號`、`厚度`、`寬度`、`長度`、`肚`、`類別`、`備註`。
2. `manual_reviews` 固定欄位依序為：`來源表格`、`來源件號 / 項次`、`問題欄位`、`目前判斷`、`需確認內容`、`影響範圍`。沒有事項時不得輸出空表。
3. 每筆 `manual_reviews` 的 `來源表格` 與 `來源件號 / 項次`，優先精確對應本輪完整 `ocr_result` 的 `來源` 與 `零件編號`。件號缺漏或重複時，填 `來源表格=ocr_result`，並以完整訂單資料列項次填入 `來源件號 / 項次`（從 1 起算，不含表頭），使每項問題可定位至唯一來源列。缺項即使沒有對應的報價列，也要用該來源列定位，並在 `問題欄位` 明示缺少的材料或加工項目。
4. `system_order` 只保留一個標題、一張表頭及完整資料列。
5. `manual_reviews`（若有）必須是最後一張表，其他適用補充 Markdown 依既有輸出規則排在它之前。
