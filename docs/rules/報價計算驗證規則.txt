【Steel 報價計算驗證規則】

一、`system_order`總數與`customer_quote`報價共用逐列結果

1. 產生`## system_order`時，`單重`與`總數`必須依該列已選 candidate 的`類別`與對應的個別鋼材／加工規則，使用本輪 OpenAI Python 計算。不同類別的計重、計長、計件、刀數、孔數或其他計價量公式不得混用；通用規則不得覆蓋個別類別規則。`system_order`.`總數`必須保留該類別結果的精確、未四捨五入計價量，供`## customer_quote`使用。
2. `總數`依計價種類分行計算：
   - Kg類：依該鋼材類別的計重公式算出全部數量的精確總kg，填入`總數`。
   - M類：依該鋼材類別的長度規則算出全部數量的精確總m，填入`總數`。
   - 件／支類：依該鋼材類別的配料、母材與整件規則得到實際計價件數／支數，填入`總數`。
   - 加工計數類：依該加工類別規則計算孔數、刀數、折數或其他實際計價量，填入`總數`。
   - 個別類別例外：存在專用計價或加成規則時，必須以該類別規則計算`總數`，不得改套上述其他種類。
3. `system_order`.`計價基準`取客戶等級（未提供時預設B=2）；`單價`不是 Python 推導值，只能精確複製同一個最終已選 candidate 中與`計價基準`對應的`tierPrices`價格。`## system_order`必須依來源順序保留唯一且有序的逐列結果；每列至少包含來源列識別、candidate 識別、`類別`、精確`總數`、`計價基準`與對應`單價`。
4. 產生`## customer_quote`時不得再用尺寸、單重或其他公式重算`總數`；每筆`小計`只能使用`## system_order`同一列的精確`總數 × 單價`，再將該列結果以`ceil`進位成TWD整數。不得使用另一個 candidate、其他 tier 價格、說明中的四捨五入重量或前一輪結果。
5. 正確範例：來源`CS13`為鐵板`PL6*54`、長54mm、15件、density 7.85。`## system_order`依鐵板類別公式得到精確單重=`6*54*54*7.85/1000000=0.1373436`、精確`總數=2.060154`，並從 candidate 取得`單價=38.5`；`## customer_quote`只計算`ceil(2.060154*38.5)=80`。不得把鐵板寬54誤用為60而得到`總數=2.289`，也不得在`## customer_quote`重算出與`## system_order`不同的總數。
6. 正確逐列進位範例：`CP21`在`## system_order`的精確`總數=15.361665`、candidate `單價=38.5`，`## customer_quote`的未進位小計=`15.361665*38.5=591.4241025`，因此材料小計必須是`ceil(591.4241025)=592`。填569屬錯誤；鑽孔列在`## system_order`的`總數=20`、`單價=7`，`## customer_quote`另算`ceil(20*7)=140`，不得與材料小計混算。

二、畫面小計與總計驗證

1. `小計 = ceil(總數 × 單價)`。產生`## customer_quote`時必須使用 Python 逐列計算；`總數`或`單價`任一空白時，該列`小計`留空並列入`## manual_review`。
2. `總計 = 畫面所有非空白小計加總`。產生`## customer_quote`時必須使用 Python `sum(...)`；空白小計不加入、不以0代替，且不得使`總計`留空。沒有非空白小計時，`總計=sum([])=0`。
3. 輸出`## customer_quote`前只做兩項核對：畫面非空白小計筆數必須等於 Python array 筆數；畫面`總計`必須等於該 array 的 Python `sum(...)`。array 只放畫面實際顯示的非空白小計，不得加入隱藏列、總計列、前一輪結果或重複列。任一核對不通過時先修正再輸出；核對值不新增為 Markdown 欄位或輸出列。
