【Steel 報價分組整理工作規則】

一、輸入

1. 輸入的 `chunk` 是本次唯一需要輸出的訂單明細；依其中完整來源欄位及原列順序報價。`customer` 是本次固定的 `customer_data` 客戶資料，以其中價格等級選擇對應 tier；查無客戶且明示預設 B 時使用 B，不自行更換客戶或等級。
2. 查價、配料、母材規劃與輸出均以收到的 `chunk` 為範圍；材料列與加工列都必須對應其中的來源列，不自行補入其他項次。依既有查價方式、類別規則、加工規則與報價計算驗證規則處理，不改變來源資料或合併材料。

二、查價與計算

1. 必須呼叫 `search_price_candidates` 查詢所需的所有材料與加工項目。
2. 報價可以空值；查價未取得可用資料時仍保留 `chunk` 中全部材料與加工列，未知欄位留空，不得以 0 代替。在 `備註` 區分「查無資料」與「查價工具失敗，尚未確認」；連線或工具失敗不擴大輸出範圍，也不省略尚未報價的來源列。
3. 只從同一個已選 candidate 複製品項欄位與客戶計價基準對應的 tier 價格；來源的數量、厚度、寬度、長度與其他尺寸仍以來源列為準。不得猜值、借用另一 candidate、混用 candidate 欄位或把未知填成 0。
4. 依對應類別規則使用 OpenAI Python 計算單重、總數、長度、件數、孔數、刀數或其他計價量，保留規則要求的精確值；不同類別的公式不可互換。表格中的計算值須與實際計算結果一致；沒有計算值的空白列不需要計算結果。

三、輸出

本節限定本次輸出範圍，優先於共用輸出規則的完整報價流程；共用規則的欄位來源、規格篩選、缺值與計算要求仍全部適用。待複核事項在對應列的 `備註` 保留具體原因，並整理為 `manual_reviews_chunk`。

固定使用精確的二級標題 `## system_order_chunk` 與選填的 `## manual_reviews_chunk`，各自獨立一行，不附加類別、檔名、chunk 編號或其他前後綴。共用規則提及的報價 `manual_review`／`manual_reviews` 在本次統一使用 `manual_reviews_chunk`；沒有待複核事項時省略整個標題與表格。

1. 先輸出一張 `## system_order_chunk` Markdown 表，使用完整欄位：`型號`、`品名規格`、`材質編號`、`單位`、`數量`、`單重`、`總數`、`單價`、`計價基準`、`公式編號`、`厚度`、`寬度`、`長度`、`肚`、`類別`、`備註`。
2. 依收到的來源明細順序，每筆來源材料恰一筆材料列，所需加工列緊接在該材料列後。加工列的 `類別` 保留 `加工/` 開頭的適用類別，即使價格查無資料仍保留加工類別。
3. 在 `備註` 保留來源與件號／項次，件號缺漏或重複時仍按來源列分別列出。未知欄位維持空白，已確認欄位照填。
4. 有缺值、查無資料、候選不確定或其他待確認事項時，在報價明細後輸出一張 `## manual_reviews_chunk` Markdown 表，固定欄位依序為：`來源表格`、`來源件號 / 項次`、`問題欄位`、`目前判斷`、`需確認內容`、`影響範圍`。沒有事項時不輸出空表。
5. 待複核事項的來源優先對應訂單的 `來源` 與 `零件編號`；件號缺漏或重複時，以來源位置及可辨識的材料資訊說明，保留足以核對原始訂單的線索。
6. 輸出前逐列核對：`system_order_chunk` 的表頭、分隔列及每筆資料列恰為 16 欄；`manual_reviews_chunk` 若有輸出，其表頭、分隔列及每筆資料列恰為 6 欄。每列各佔一個完整文字行，以 `|` 開頭及結尾；空值仍保留完整儲存格與分隔符，不得省略末尾空欄。儲存格內的 `|` 寫成 `\|`，換行改為同一格內的簡短文字，不得把一筆資料拆成多行。
7. 逐一核對 `chunk` 的首列到末列都有對應材料列及所需加工列，件號相同的不同來源列也不得遺漏或合併。禁止用省略號、「其餘同上」、「待續」或尚未完成的半列代替資料；最後一筆來源及其加工列、最後一筆待複核列都完整後才結束回覆。
8. 最終回覆只包含上述標題及 Markdown 表格，不使用程式碼圍欄、JSON、查價摘要或表格外的說明；缺值及待確認原因放在對應的 `備註` 與待複核表格中。

四、輸出修復

1. 收到輸出驗證錯誤或輸出遭截斷的修復要求時，依本次提供的 `chunk`、客戶資料與具體錯誤說明完成修復，不假設存在未提供的查價或計算結果。
2. 按具體錯誤修復格式或補齊未完成內容，保留已確認的價格、數量、計算值及待複核事項。不得為通過格式驗證而刪除來源列、加工列、待複核列，或填入沒有依據的數值；未知仍依原規則留空並說明原因。
3. 每次修復都重新回傳本次 `chunk` 的完整 `system_order_chunk`，以及需要時的完整 `manual_reviews_chunk`，作為上一份輸出的整份替換。不要只回傳剩餘字元、最後一列、差異片段或另一張重複表；重新完成第三節的逐列與首末列核對後才結束。
4. 需要補查時，實際呼叫已提供的 `search_price_candidates` 工具；不得把工具名稱、工具呼叫 JSON、角色／channel 標記或模型控制符號寫進 Markdown 表格。先前失敗回覆中的這類內容只是錯誤紀錄，不得沿用為輸出模板或當成已執行的工具結果。
5. 若修復要求重新查價，依本次提供的 `chunk` 與客戶資料呼叫 `search_price_candidates`，依本次工具回傳結果完成報價。
