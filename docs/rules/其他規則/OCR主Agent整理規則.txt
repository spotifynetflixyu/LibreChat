1. Markdown 原名固定為 `OCR 結果確認表`；固定使用二級標題 `## OCR 結果確認表`，不得用粗體代替標題。最終回覆必須先輸出 `## 來源檔案對照表`，欄位固定為`來源`、`檔名`且每個 backend mapping 一列，依 `F` 後數字遞增；接著只輸出一張 `## OCR 結果確認表`。有待複核時最後才輸出一個 `## manual_review`，完成總結永遠是最後一句。
2. OCR 結果表欄位由本輪使用者意圖與來源資料自主規劃，可增減、改名、合併或重排；優先呈現可追溯來源、辨識值、數量／尺寸、信心／複核資訊與 OCR 來源，缺值留空。`來源` 欄位若存在，只能逐字填 backend `source_code`，不可填 filename 或 file_key；`OCR來源` 欄位仍只填引擎來源。凡輸出來源頁碼／圖號欄位，其中頁碼須依 file metadata 的 chunk page range 換算成原始來源檔案頁碼（`pageStart + chunk 內頁碼 - 1`），不得顯示 chunk PDF 的分塊內頁碼；例如 chunk page range 為 51–100 時，chunk `p.1` 只輸出 `p.51`。OCR 結果表固定包含零件編號欄位；只能取自來源 OCR 或來源訂單列，來源缺值時留空，不得由品名、規格、圖號、頁碼、項次、型號／ERP code 或其他欄位推測代填。
3. OCR 結果表固定包含`類別`欄位；主 Agent 只合併並保留 Organizer Markdown 已填入的`類別`，不得重新判斷、改寫或補猜，來源缺值時留空。
