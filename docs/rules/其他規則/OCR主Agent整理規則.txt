【OCR 主 Agent 整理與合併規則】

[delegate_ocr]
1. 依完整對話、最新使用者問題與本輪提供的原始 image/PDF 回答。
2. 先依可見對話判斷最新 user intent 再回應；任務可包含 OCR 解析、Vision 圖面核對、特定問題回答、資料比對或表格整理，不得把「整理 Markdown」視為唯一任務。
3. 重新確認時以原始 image/PDF 為權威來源，直接處理使用者問題；不得用既有 OCR 整理結果取代原始檔案。
4. answer 可為純文字或 Markdown；依 user intent 需要回答，只有問題要求表格或彙整時才使用對應 Markdown，不強制產生 OCR 表格。
5. 不呼叫 tool、subagent 或 MCP，不查價、不產生正式報價。無法從來源確認時應明確說明，不得改成推測結果。
[/delegate_ocr]

[ocr_main_merge]
1. 依來源檔案分組，同一來源的已整理內容合併成一張 OCR 結果確認表；不同來源不混表。
2. 合併時保留每筆來源列，不彙總、不合併同品名／規格，並維持來源頁數、項次、件號、圖號或其他可追溯代號。
3. 欄位以已提供的整理內容為準；缺值保持空白，信心與複核原因保留在同一列，不重新辨識來源、不查價、不產生正式報價。
4. 本輪 OCR 預處理提供的整理後 Markdown 是由 raw PaddleOCR text 產生，屬於 PaddleOCR 結果。合併時必須保留 `PaddleOCR` 來源；舊整理內容若未附來源標籤，應補標 `PaddleOCR`，不得推定為 `AI OCR`。
[/ocr_main_merge]

[final_ocr_markdown]
1. Markdown 原名固定為 `OCR 結果確認表`；標題依通用格式輸出為 `## OCR 結果確認表｜<filename>（<file_key>）`，檔案資訊只是原名後的補充。
2. 每列依來源與報價需要包含品名／規格、尺寸／厚度、數量／單位、孔數、折邊、割型、開槽連續邊長、切角、缺口、輪廓、信心與複核原因；缺值一律留空。
3. OCR 或 Vision 已修正的內容直接使用修正值，並在同列`備註`保留原辨識值、修正內容與原因。
4. 模糊、缺字、遮擋、反光、低解析、字元歧義、規格／數量／尺寸不完整、列數不一致或需 Vision 幾何判讀時，在同一表的信心／複核欄標示，不另建立第二張複核表。
5. raw PaddleOCR text、OCR 子 Agent 整理結果，以及本輪提供的整理後 OCR Markdown，都是同一條 PaddleOCR 來源鏈；AI 的整理、合併、格式化或文字修正不會把來源變成 AI OCR。沒有看到 raw payload、工具事件或原始 PaddleOCR 回傳，不代表 PaddleOCR 失敗。
6. 不論輸出格式，每筆 OCR 資料都要標示來源，欄位與位置由模型決定：只使用 PaddleOCR 來源鏈時標 `PaddleOCR`；另由 AI OCR／Vision 直接讀取原始附件補充或修正欄位時標 `PaddleOCR/ AI OCR`；只有收到明確的 PaddleOCR 失敗或不可用結果，且該筆資料完全由 AI OCR 取得時才標 `AI OCR`。
7. 不得因內容已整理成 Markdown、經過 AI 處理或缺少 raw payload 而改標 `AI OCR`，也不得宣稱未取得 PaddleOCR 資料。資料優先為 `PaddleOCR` > `AI OCR`；AI OCR 不得覆蓋、漏標或降級 PaddleOCR。
[/final_ocr_markdown]
