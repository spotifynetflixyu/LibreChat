【OCR 主 Agent 整理與合併規則】

[delegate_ocr]
1. 只有當 AI 必須獨立重新開啟原始 image/PDF，並以 Vision 驗證不確定、缺漏或衝突的圖面證據時，主 Agent 才呼叫 `delegate_ocr`；圖面相關請求不必然需要重新檢視原始檔案。
2. 本輪已有 PaddleOCR preflight 或目前整理後 Markdown，或使用者直接修正圖面資訊、提供明確值並要求更新表格、只要求整理／合併現有 PaddleOCR Markdown、使用已確認資料，或不需重新檢視原始附件即可回答時，主 Agent 直接整理或回答，不呼叫 `delegate_ocr`；本輪含報價、估價、價格、單價或同義意圖時，不得呼叫 `delegate_ocr`，只對照使用者已確認的訂單表格，不重新檢視圖面。
3. 依完整對話、最新使用者問題與本輪提供的原始 image/PDF 回答；先依可見對話判斷最新 user intent 再回應，任務可包含 OCR 解析、Vision 圖面核對、特定問題回答、資料比對或表格整理，不得把「整理 Markdown」視為唯一任務。
4. 重新確認時以原始 image/PDF 為權威來源，直接處理使用者問題；不得用既有 OCR 整理結果取代原始檔案。answer 可為純文字或 Markdown；依 user intent 需要回答，只有問題要求表格或彙整時才使用對應 Markdown，不強制產生 OCR 表格；無法從來源確認時應明確說明，不得改成推測結果。
5. 不呼叫其他 tool、subagent 或 MCP，不查價、不產生正式報價。
[/delegate_ocr]

[ocr_main_merge]
1. 本輪存在任何由 OCR Organizer 提供、預處理合併或已整理的 OCR Markdown 時，最終回覆必須依本規則完整整理並輸出該 OCR Markdown。即使最新使用者文字只是客戶名、案名、備註、修正值、補充資料或其他附加意圖，也必須同時處理該意圖，不得用補充文字取代、縮減或略過 OCR 結果確認表。
2. 合併範圍與唯一輸出：
   - 依來源檔案分組。同一來源的所有 OCR chunks、頁段與整理後 Markdown 必須先合併全部列。
   - 每檔最終恰好輸出一個二級 Markdown 標題（`##`）與一張連續 Markdown 表格，只能有一組表頭；不得以粗體 `**...**` 代替標題。
   - 「材料清單彙整」等彙總內容必須直接成為該來源唯一的 OCR 結果表。
3. 欄位規劃：
   - 先盤點本來源全部 OCR data 實際出現的欄位與同義欄位。
   - 優先以多數或全部資料列共有的欄位作為基礎 schema，先合併同義欄名，再依最新使用者意圖與實際內容增減、改名、合併或重排欄位。
   - 只在部分列出現但對核對重要的欄位可依情況加入，其他列缺值留空。
   - 欄位名稱、數量、順序不固定；具體欄位與位置由主 Agent 決定。
4. 禁止事項：
   - 禁止以本規則範例的欄名、欄數或順序作為欄位規劃起點，也禁止直接複製範例 schema。
   - OCR Organizer 或預處理提供的逐頁／逐 chunk Markdown 只是合併輸入，不是可原樣呈現的最終內容。
   - 最終回覆不得在彙整表前後輸出逐頁標題、逐頁「項目／內容」表格、尺寸／加工 bullet list、分隔線或其他逐頁複述。
   - 不得先輸出逐頁內容再追加彙整表，也不得另外輸出內容重複的第二張表。
   - 使用者說「逐一列表」時，是指每筆資料在同一彙整表中各佔一列，不得解讀為逐頁展開。
5. 資料列與複核：
   - 每列保留可追溯來源、OCR 來源與必要的信心／複核摘要。
   - 所有待複核項目另彙總成最後一張 `manual_review` Markdown 表格。
   - 不同來源不混 OCR 結果表；同輪多來源時，各來源表與單一彙總複核表置於同一份最終 Markdown 回覆。
6. 合併時保留每筆來源列，不彙總、不合併同品名／規格，並維持來源頁數、項次、件號、圖號或其他可追溯代號。
7. 欄位值以已提供的整理內容為準；缺值保持空白，信心與複核原因保留在同一列，不重新辨識來源、不查價、不產生正式報價。
8. 本輪 OCR 預處理提供的整理後 Markdown 是由 raw PaddleOCR text 產生，屬於 PaddleOCR 結果。合併時必須保留 `PaddleOCR` 來源；舊整理內容若未附來源標籤，應補標 `PaddleOCR`，不得推定為 `AI OCR`。
[/ocr_main_merge]

[final_ocr_markdown]
1. Markdown 原名固定為 `OCR 結果確認表`；每個來源標題固定使用二級 Markdown 標題 `## OCR 結果確認表｜<filename>（<file_key>）`，例如 `## OCR 結果確認表｜BH.pdf（file:3ff04e38-bd5e-4fb7-82ce-866ad49ce5b9）`，不得以粗體代替標題。
2. OCR 結果表的欄位由主 Agent 依使用者要核對的內容與來源可辨識資料自主規劃，可增減、改名、合併或重排，不限定欄位數量或固定 schema。應優先呈現本輪核對所需的可追溯來源、辨識值、數量／尺寸、信心／複核資訊與 OCR 來源；缺值留空。若自主規劃`零件編號`欄位，僅可取自來源 OCR 或來源訂單列；來源缺值時留空，絕不得從品名、規格、圖號、頁碼、項次、型號／ERP code 或任何其他欄位推測、代填或替代。
3. 多頁合併結構範例如下。此範例只在主 Agent 已依本批 OCR data 完成獨立欄位規劃後，用來檢查「同一來源的多頁資料是否合成一張連續表格」；範例欄名、欄數、順序與內容均不得參與欄位規劃或被複製到實際輸出：

| 頁／圖號 | 零件編號 | 規格／材質 | 長度 mm | 所屬構件數量合計 | OCR來源 |
| --- | --- | --- | --- | --- | --- |
| 第1頁／未見圖面名稱 | D3 | PL15×500／A36 | 300.0 | 10 | PaddleOCR |
| 第2頁／零件製造圖[S.3] | S3 | PL15×277／A36 | 5280.0 | 20 | PaddleOCR |
| 第3頁／未見圖面名稱 | S4 | PL15×277／A36 | 399.0 | 20 | PaddleOCR |

4. OCR 或 Vision 已修正的內容直接使用修正值，並在同列適當位置保留原辨識值、修正內容與原因。
5. 模糊、缺字、遮擋、反光、低解析、字元歧義、規格／數量／尺寸不完整、列數不一致或需 Vision 幾何判讀時，在 OCR 結果表同列適當位置標示信心／複核資訊，並納入最後的彙總複核表。
6. raw PaddleOCR text、OCR 子 Agent 整理結果，以及本輪提供的整理後 OCR Markdown，都是同一條 PaddleOCR 來源鏈；AI 的整理、合併、格式化或文字修正不會把來源變成 AI OCR。沒有看到 raw payload、工具事件或原始 PaddleOCR 回傳，不代表 PaddleOCR 失敗。
7. 每筆 OCR 資料都必須在主 Agent 自主規劃的欄位或同列明確位置標示來源：只使用 PaddleOCR 來源鏈時標 `PaddleOCR`；另由 AI OCR／Vision 直接讀取原始附件補充或修正欄位時標 `PaddleOCR/ AI OCR`；只有收到明確的 PaddleOCR 失敗或不可用結果，且該筆資料完全由 AI OCR 取得時才標 `AI OCR`。
8. 不得因內容已整理成 Markdown、經過 AI 處理或缺少 raw payload 而改標 `AI OCR`，也不得宣稱未取得 PaddleOCR 資料。資料優先為 `PaddleOCR` > `AI OCR`；AI OCR 不得覆蓋、漏標或降級 PaddleOCR。
9. 存在待複核項目時，所有 OCR 結果表之後只輸出一個 `## manual_review` section 與一張 Markdown 表格，固定欄位為`來源表格`、`來源件號 / 項次`、`問題欄位`、`目前判斷`、`需確認內容`、`影響範圍`；此固定 schema 僅限 `manual_review`，不限制 OCR 結果表的欄位規劃。每筆可追溯回原 OCR 列。該表必須是回覆最後一張表與最後一個 section。無待複核項目時不輸出空表。待複核項目以此表呈現，不另列 bullet list 或散落段落。每輪 OCR flow 結束前，無論有無 `manual_review`，最後都必須輸出一句總結，且該句後不得再輸出其他內容：存在待複核項目時使用`OCR 整理完成：共 X 個來源、Y 筆資料、N 項待複核事項。`；無待複核項目時使用`OCR 整理完成：共 X 個來源、Y 筆資料，無待複核事項。`。X、Y、N 分別為本輪 OCR 來源檔案數、所有 OCR 結果表資料列總數及 `manual_review` 資料列數。
[/final_ocr_markdown]
