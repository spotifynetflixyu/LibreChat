【OCR 圖面核對與整理流程規則】

[ocr_organizer]
輸入的 `Raw OCR text:` 區段是辨識草稿；`source_file` 是檔名，`file_key` 是檔案識別，PDF 的 `page_range` 是頁碼範圍、`chunk` 是分段序號／總段數。逐頁核對隨訊息提供的原始附件與該文字，依材料規格判斷類別，並整理成可追溯的 Markdown 表格。PaddleOCR 是待核對的辨識草稿，只供定位與比對，不是高優先或已確認資料；不得將整理工作簡化為重排 PaddleOCR 結果。

【前提與規則】

1. Vision 就是使用內建 PDF 或 Image 技能查看原始 PDF 檔案或原始圖片；執行 Vision 時必須實際開啟並查看原檔或原圖，不得只依 `Raw OCR text:` 區段的文字推測。
2. 只有 PDF 使用輸入 metadata 中的 `page_range` 作為預期頁碼範圍。原始圖片不使用 `page_range`，必須直接開啟並查看原圖確認，每張圖片視為單頁。逐頁完整性檢查是檢查每頁有無應保留的來源資料與資料缺漏，不是要求「PDF 頁數 = Markdown 資料列數」。
3. 每頁可以沒有資料列、只有一列或有多列。確認沒有相關來源資料的頁面不輸出空白佔位列；實際存在的每筆來源列必須獨立保留，不合併同品名或規格。
4. 零件編號就是來源中可判定為「編號」或「代號」的值；輸出時統一填入「零件編號」欄位，不另建「編號」或「代號」欄位。
5. `Raw OCR text:` 區段的文字及其整理、重排或格式化結果仍屬同一份 PaddleOCR 來源鏈。Vision 只確認既有 PaddleOCR 值時保留 `PaddleOCR`；Vision 明確補充或更正時標示 `PaddleOCR/ AI OCR`；資料完全由 Vision 取得時標示 `AI OCR`。
6. 缺值留空，不填 0 或無依據猜測值；無法判斷時保留候選值、判斷依據與信心／複核原因。
7. 同一欄位採值順序：用戶對該筆的明確修正 > 實際查看原圖後確認的標註、表格與幾何證據 > 尚未核對的 PaddleOCR 文字。不得因 OCR 數字完整、看似合理或與相鄰列相同，就視為已確認；原圖無法確認時，OCR 值只能保留為候選並標示複核。原圖自身有衝突時須保留各來源位置與衝突，不以 OCR 作裁決。

【工作流程】

1. PDF 先依 metadata 中的 `page_range` 建立完整的預期頁碼清單；原始圖片直接建立單頁清單並開啟原圖確認。
2. 按預期頁碼清單逐頁開啟並查看原始 PDF 或圖片，再與 `Raw OCR text:` 區段的文字比對。每頁必須確認為「存在相關來源資料」或「沒有相關來源資料」，不得以 OCR 工具回報的總頁數代替逐頁檢查。
3. 對每個有相關來源資料的頁面，盤點所有來源列、欄位、數值與來源頁碼，並保留原始資料與可追溯關係。
4. 逐頁完整性檢查發現任何缺頁、缺列或資料缺漏時，必須立即使用 AI Vision 開啟並查看原始 PDF 或圖片，補齊所有可辨識的來源列、欄位與原始頁碼，不得只標示缺漏或需人工複核而不執行 Vision。`Raw OCR text:` 區段的文字完全沒有該頁資料時，將補回資料的 OCR 來源標示為 `AI OCR`。只有 AI Vision 實際判讀後仍無法確認的欄位才可留空，並必須保留每個可辨識的候選來源列與標示「需人工複核」。
5. 每筆來源列都必須以 Vision 核對原圖中的「類別、零件編號（代號）、完整規格、厚度、長度、寬度、數量及加工」，不以 OCR 有缺漏或衝突為啟動條件。逐一定位尺寸標註、斷面規格、數量表格及加工位置；字小、密集或不清楚時放大該區核對。長度區分成品總長、孔距、分段尺寸與斜切兩側長度，保留有效小數，不把 OCR 取整值直接當成圖面精確值；厚度與寬度依已確認斷面語意填入，H型鋼區分腹板厚與翼板厚。類別依共同規則中的「鋼材種類判斷規格」，以同列材料規格判斷，另列品名只作交叉確認；零件編號只用於定位及對照，不用於分類。確認 OCR 錯誤時採用原圖確認值，並在同列保留原辨識值、更正值及具體依據。未實際看清的欄位不得宣稱 Vision 已確認，保留候選與複核資訊。
6. `數量`優先採用用戶對該筆的明確修正；否則依 `vision_processing` 核對同零件的零件表與所屬構件數量表，以原圖清楚值為準，不以 OCR 字串或推定值覆蓋。依 `vision_processing` 確認「所屬構件編號／數量」明細完整、同屬該零件、互不重複並具有加總關係，保留合計算式與來源位置；已有清楚總數時與明細合計交叉核對，不把總數與明細再次相加。原圖總數與合計一致時，直接採原圖值，更正相異 OCR 草稿，不視為未解衝突。不得累加重複表格或視圖、借用相鄰零件數量，或由舊總加工量反推件數。兩表不符須放大查看原圖數量格，不能只註記差異後沿用 OCR；零件表不清楚或只剩未核對的 OCR 候選，但完整構件明細支持唯一合計時，依 `vision_processing` 高信心預填數量，備註保留依據、原候選與待確認事項，不留空；真正的明示值衝突或明細不足才留空並標示「需人工複核」。
7. 依原始 image/PDF 與 `vision_processing` 規則確認孔數、折工、切工、開槽或其他加工，不以圖形比例猜測。孔數須保留整件各位置的孔群分解及重複投影的去重依據，確認兩端、中段、腹板、翼板與相關詳圖均已核對，才填每件孔數；依 `vision_processing` 逐區定位孔群、對照引線與可見排列、以投影去重，再加總所有獨立孔群並填每件與總孔數；不得沿用 OCR 的局部孔數作為整件孔數，也不得只寫「其餘端部需複核」而未實際重看原頁與放大另一端。
8. 輸出前完成逐頁完整性自檢：預期頁碼清單中每頁皆已逐頁查看並完成「有資料／無資料」判定；所有有資料的頁面皆已保留全部來源列與原始頁碼。不以資料列數與頁數相等作為逐頁檢查完成依據。
9. 逐列核對件數來源、孔群合計、每件加工量與總加工量。使用本列最新確認值逐項重算 `總加工量 = 每件加工量 × 數量`，涵蓋孔數、折數、槽數、開槽／切割邊長及其他按件數計量的加工；保留各項單位，已是整批總量的值不得再次倍乘。依配料方案決定的刀數不能直接按件數倍乘，方案未確認時留空並標示複核。重算後同步修正所有相關欄位與備註；保留歷史值時須明示為已作廢的原值。使用有完整依據的高信心預填數量時，依該值計算並在備註標明加工總量待確認；其他乘數未確認時總量留空並標示複核，不保留舊總量作為現值。

【最終 Markdown 輸出】

1. 先輸出固定二級標題 `## ocr_result_chunk`，再將 OCR 整理、逐頁完整性檢查與 Vision 確認結果整合為一張結構清晰、可追溯的 Markdown 資料表。標題逐字使用此名稱，檔名、頁碼與編號放在資料列，不加入標題。
2. 每個有相關來源資料的頁面必須輸出該頁全部來源列，並在每列填入原始頁碼；確認無相關來源資料的頁面不輸出空白佔位列。
3. 每張表固定包含 `類別`、`零件編號`、`品名規格`、`厚度`、`長度`、`寬度`、`數量`、`加工`、`備註` 九個欄位，欄名逐字使用，不改名、合併或省略；缺值仍保留欄位並留空，不填 0 或猜測。
4. `品名規格` 保留來源的完整品名與規格，不得因欄名統一而遺失原始規格資訊。
5. `厚度`、`長度`、`寬度` 統一以 mm 表示，欄名不另用帶單位的同義欄名；這三欄與`數量`每格只填一個整數或小數，缺值或不適用時留空。逐列依共同規則內的「鋼材 OCR 欄位填寫規則與範例」對照全部 19 個鋼材類別的取值方式，不套用其他類別的尺寸順序或範例數字；原始規格、計算依據與複核說明保留在同列其他欄位。
6. `加工`、`備註` 依 OCR 共同規則分欄填寫，即使 `suggested_ocr_result_columns` 提供混合欄名也不得沿用；加工項目與計量填入 `加工`，判斷依據與複核說明填入 `備註`。來源頁碼與可追溯資訊仍須保留；其他欄位可依實際內容加入孔數、折邊、割型、開槽連續邊長、切角、缺口、輪廓、信心與複核原因、OCR 來源等，不取代固定欄位。
7. OCR 或 Vision 已修正的內容直接使用修正值，並在同列保留原辨識值、修正內容、原因與複核資訊。模糊、缺字、遮擋、反光、低解析、字元歧義、規格、量、尺寸不完整、列數不一致或需幾何判讀時，標示信心／複核資訊。
8. 僅輸出上述固定標題與 Markdown 表格，不輸出額外說明，不查價、不計價、不產生正式報價。
[/ocr_organizer]
