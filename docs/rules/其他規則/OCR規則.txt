【OCR 共同規則】

[ocr_shared]
1. 本共同規則適用所有 OCR / Vision 文字處理與資料整理情境，包括一般 OCR、預處理整理及需要重新檢視原始檔案的情境。
2. 讀取文字或圖面前，先確認圖面與文字方向；有旋轉或傾斜時先轉正，再進行 OCR 文字辨識、資料整理或 Vision 圖面判讀。
3. PaddleOCR 文字是待核對的辨識草稿，只供定位與比對，不高於原始圖片或 PDF 的清楚證據。收到 `Raw OCR text:` 區段及原始附件、依 `ocr_organizer` 輸出 `ocr_result_chunk` 時，須逐頁、逐列使用 Vision 核對長、寬、厚、數量與加工，即使 OCR 值完整或看似合理也不能免除核對。用戶明確修正優先；否則採原圖確認值，保留來源列、原始規格、數值與來源頁碼或代號。只接收 `ocr_result_chunk` 或 `previous_ocr_result_markdown` 等整理結果時，沿用其輸入邊界，不重新看圖。
4. `Raw OCR text:` 區段的文字與其重排、合併或格式化結果都須保留原始來源鏈；不得因整理方式改變而省略來源或另造資料。
5. 整理 OCR Markdown 時，先盤點 OCR 與 Vision 實際確認的全部欄位與同義欄位，再依資料內容與對應階段的固定欄位要求規劃表格。純 OCR 文字整理不加入來源未出現的資料；依 `ocr_organizer` 核對原始附件時，可依原圖補齊或更正 PaddleOCR 漏讀、誤讀的內容，並保留具體依據，不受「`Raw OCR text:` 區段未出現」限制。
6. 所有 OCR Markdown 表格都必須包含`類別`與`零件編號`欄位；凡來源欄位判定可為「編號」或「代號」時，其值一律預設為零件編號，輸出時全部填入「零件編號」欄位，不得另行保留、新增或輸出「編號」欄位。零件編號僅可填 OCR 或來源訂單列明確出現的值，來源缺值時留空，不得從品名、規格、圖號、頁碼、項次、型號／ERP code 或其他欄位推測或代填。
7. `類別`每列填入一個已判定的類別，只能使用：`鐵板`、`C型鋼`、`方鐵`、`H型鋼`、`T型鋼`、`板/浪板`、`平鐵`、`角鐵`、`鋼筋`、`圓管`、`鐵軌`、`槽鐵`、`I型鋼`、`方管`、`扁方管`、`圓條`、`網`、`格板/隔板`、`其他`。不得填自創值或未明列值；無法確認時留空並標示需人工複核，不得猜測。
8. 文字、數字、符號、尺寸或重量不清時，不以「約、略、大約、約略」等近似詞代替。依 `ocr_organizer` 核對原始附件時，須放大原圖相關區域，依同零件的表頭、單位、標註與重複明示值交叉核對，不以相鄰零件值補猜。仍無法確認時，欄位留空；但數量符合 `vision_processing` 的完整構件明細高信心預填條件時，須預填並保留採值依據及待確認狀態，不因 OCR 候選衝突而清空。候選值、來源位置與複核原因保留於備註；不得把最像或最合理的 OCR 候選直接當成已確認值參與加工總量計算；依高信心預填數量計算的總量須明示預填依據與待確認狀態。
9. 明顯 OCR 字元誤判可依欄位脈絡修正，但須在備註保留原辨識值、修正值與原因；算式中的數值或公式結果不清時不得自行補齊。
10. 純 OCR 文字整理只保留文字明示的加工，不自行做幾何判斷；依 `ocr_organizer` 核對原始附件時，必須依 `vision_processing` 查看原圖確認加工及計量，不能因 PaddleOCR 未讀出孔或加工標註而省略。未確認資料留空並標示複核。
11. `ocr_result_chunk`、`ocr_result` 與 `ocr_result_updates` 資料表固定分別包含 `加工`、`備註` 兩個獨立欄位，缺值仍保留欄位並留空，不得合併為 `加工／備註`、`加工/備註` 或其他混合欄名。`加工` 填已確認的加工項目、加工規格、每件加工量與總加工量，保留計量單位；依高信心預填數量計算時，備註同步標明總量待確認；多項加工以分號分隔。`備註` 填一般說明、來源位置、孔群分解、計算與判斷依據、原辨識值與修正原因、候選值及複核原因，不得只把已確認的加工項目放在備註。加工項目已確認但計量未確認時，保留項目，不填猜測量，候選與複核原因放入備註。
